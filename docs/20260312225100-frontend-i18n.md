# 主题：frontend-i18n

## 记录

### 2026-03-12 22:51:00

## 本次目标
- 为桌面端前端增加中英文国际化能力。
- 在尽量少改动现有大体量中文文案的前提下，先完成可切换、可运行、可验证的双语方案。

## 关键改动
- 前端 `apps/desktop/src/i18n/messages.ts`
  - 新增前端国际化词典与规则翻译，覆盖主界面、常用提示、弹窗按钮、动态标题等高频文案。
  - 支持中英文双向转换，并对带变量的动态文本使用正则规则做运行时翻译。
- 前端 `apps/desktop/src/i18n/index.ts`
  - 新增全局语言状态、`localStorage` 持久化、`document.lang` 同步。
  - 接入 Ant Design Vue 的 `zh_CN` / `en_US` locale。
  - 对 `message`、`Modal` 做运行时封装，自动翻译通知和弹窗文案。
  - 新增 DOM 观察式翻译层，对现有模板里的静态中文文本、`title`、`placeholder` 等属性做无侵入切换。
- 前端 `apps/desktop/src/modules/studio/components/StudioShell.vue`
  - 在顶部操作区新增语言切换下拉框。
  - 将 `a-config-provider` 绑定到当前语言 locale。
  - 在工作台根组件启用 DOM 国际化同步。
- 前端 `apps/desktop/src/main.ts`
  - 应用启动时初始化国际化运行时补丁。
- 样式 `apps/desktop/src/modules/studio/styles/shell.css`
  - 为顶部语言切换器补充样式，保持与现有导航栏视觉一致。

## 方案说明
- 当前工程前端中文文案分布广、历史代码多，若一次性全部改造成 key-based i18n，改动范围会显著扩大。
- 本次先采用“全局语言状态 + Ant Design locale + 运行时翻译层”的过渡方案，优先满足中英文切换能力和界面可用性。
- 后续如继续演进，可逐步把核心模块文案迁移到标准 key/message 结构，最终替换掉 DOM 运行时翻译层。

## 验证结果
- 前端类型检查：`npm run -w @sqlcopilot/desktop type-check` 通过。
- 前端 clean 构建：`npm run -w @sqlcopilot/desktop build -- --emptyOutDir` 通过。
- 后端 clean 打包并启动：
  - `mvn.cmd -f apps/server/pom.xml clean package '-DskipTests' '-Dfile.encoding=UTF-8'` 通过。
  - `java -Dfile.encoding=UTF-8 -jar apps/server/target/sql-copilot-server-0.1.0.jar --server.port=18110` 启动成功。
  - `http://127.0.0.1:18110/api/health` 返回 `{"code":0,"message":"success","data":"ok"}`。
- 前端预览：
  - `npx vite preview --host 127.0.0.1 --port 6060 --strictPort` 启动成功。
  - `http://127.0.0.1:6060` 返回 `HTTP 200`。

## 当前边界
- 本次优先覆盖高频界面与运行时提示，未把所有前端文案完全重写为显式 key。
- 对极少数未进入词典或规则的长尾文案，英文模式下仍可能保持原语言，后续可按模块继续补齐。
