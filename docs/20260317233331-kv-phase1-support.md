# KV Phase 1 支持收口总结

## 本阶段范围

- 新增 Redis、MongoDB 两类 KV/文档存储的连接能力。
- 支持数据库列表、对象概览、对象详情、查询执行。
- AI 对话支持 KV 场景下的生成查询、解释查询、分析查询。
- KV 场景下禁用图表生成入口。
- KV 场景下不做元数据采集、缓存和向量化，改为在 AI 对话中提示用户补充必要上下文。

## 关键实现

### 后端

- `apps/server/src/main/resources/jdbc-drivers.yml`
  - 为 `MONGODB`、`REDIS` 增加 `storageKind`、`primaryObjectLabel`、`queryEditorMode` 和 AI 能力开关。
  - 显式将 `supportsGenerateChart` 设为 `false`。
- `apps/server/src/main/java/com/sqlcopilot/studio/service/kv/KvRuntimeClientFactory.java`
  - 提供 MongoDB、Redis 的运行时连接工厂，统一处理直连与 SSH 隧道场景。
- `apps/server/src/main/java/com/sqlcopilot/studio/service/impl/KvServiceImpl.java`
  - 提供数据库列表、对象概览、对象详情、查询执行能力。
  - Redis/MongoDB 均统一返回到现有查询结果模型，复用前端结果区展示。
  - KV 类型数据库列表明确返回“KV 类型不进行元数据向量化”。
- `apps/server/src/main/java/com/sqlcopilot/studio/service/impl/AiServiceImpl.java`
  - 为 KV 类型增加独立系统提示词和独立分支。
  - 当上下文不足时，明确要求用户补充 `collection/key`、字段路径、筛选条件、样例文档、索引等信息。
  - 图表生成在 KV 连接上直接拒绝，并在 Auto 模式下返回说明文本。
- `apps/server/src/main/java/com/sqlcopilot/studio/SqlCopilotApplication.java`
  - 排除 `MongoAutoConfiguration`、`MongoDataAutoConfiguration`、`MongoRepositoriesAutoConfiguration`、`RedisAutoConfiguration`、`RedisRepositoriesAutoConfiguration`。
  - 避免在应用启动时默认探测本地 `27017/6379`，改为仅在用户实际连接 KV 数据源时按需建连。

### 前端

- `apps/desktop/src/modules/studio/composables/useStudioRuntime.ts`
  - 增加 KV 概览、对象详情、对象标签、编辑器模式、执行入口分支。
  - MongoDB 查询编辑器使用 `json`，Redis 查询编辑器使用 `plaintext`。
  - KV 查询执行走 `/api/kv/query/execute`，不再进入 SQL 风险分析与 EXPLAIN 链路。
  - 根据 `supportsGenerateChart` 和 `storageKind` 动态控制图表与查询行为。
- `apps/desktop/src/modules/studio/components/StudioShell.vue`
  - 对 KV 类型动态展示“集合/键”“生成查询/解释查询/分析查询”等文案。
  - 隐藏图表生成入口、自动修复、记忆理解、样例 SQL 等仅适用于关系型数据库的操作。
  - 查询编辑器语言跟随连接类型动态切换。

## 核心设计取舍

- KV/文档存储不复用关系型数据库的元数据采集、缓存、向量化策略。
- 不为 Redis/MongoDB 臆造表结构、字段定义、索引或可视化能力。
- Phase 1 只交付连接、浏览、查询和 AI 问答适配，不扩展表编辑、ER 图、风险分析、Explain 执行计划等关系型专属能力。

## 验证结果

### 后端

- 执行：`mvn clean -DskipTests spring-boot:run`
- 结果：启动成功，`http://127.0.0.1:18080` 返回 `200`
- 结论：排除 Spring Data Mongo/Redis 自动配置后，启动日志中已不再出现默认连接 `localhost:27017/6379` 的噪音

### 前端

- 执行：`npm run build`
- 结果：构建成功
- 执行：`npx vite preview --host 127.0.0.1 --port 4173 --strictPort`
- 结果：`http://127.0.0.1:4173` 返回 `200`
- 说明：当前环境下应直接使用 `npx vite preview` 传入 `--host/--port/--strictPort`，避免 `npm run preview -- ...` 在 PowerShell 中把参数错误转发为位置参数

### 额外检查

- 执行：`npm run type-check`
- 结果：通过
- IDE 诊断中 `AiServiceImpl.java` 仍存在若干历史遗留 warning，未由本次改动新增

## 当前遗留项

- 前端生产构建仍有大包体积提示，后续可以按需做 `manualChunks` 或动态拆分优化。
- KV Phase 1 尚未覆盖真实 Redis/MongoDB 实例下的交互式端到端联调，后续应补充样例连接与实际查询回归。
- 若后续进入 GraalVM Native 打包阶段，需要继续补充 MongoDB/Redis 客户端相关的反射与资源配置验证。
