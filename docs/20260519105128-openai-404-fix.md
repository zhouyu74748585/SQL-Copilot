# OpenAI 接口 404 错误修复

## 问题描述
使用自动模式时提示 "OpenAI 接口返回状态码: 404"，用户使用第三方 OpenAI 兼容 API（qwen 模型），非 OpenAI 官方 API。

## 根因分析
`OpenAiTextClient.resolveOpenAiEndpoint()` 中的 `preferResponsesApi()` 方法在检测到模型名包含 "codex" 或以 "gpt-5" 开头时，会自动拼接 `/responses` 端点（OpenAI Responses API），但第三方兼容服务商均不支持该端点，导致 404。

此外，两台机器使用相同 key/model/提供商但一台 404，说明是本地 SQLite 中存储的 baseUrl 配置不一致。

## 修复内容

### 1. 限制 Responses API 仅在 OpenAI 官方下启用
- 文件：`apps/server/src/main/java/com/sqlcopilot/studio/service/llm/OpenAiTextClient.java`
- `preferResponsesApi()` 增加 `api.openai.com` 域名检测，第三方服务商一律走 `/chat/completions`

### 2. 404 自动降级机制
- `requestText()` 和 `requestTextStream()` 在 Responses API 返回 404 时，自动降级到 Chat Completions API 重试
- 新增 `requestTextWithFallback()` 和 `requestTextStreamWithFallback()` 降级方法

### 3. 增强错误信息
- 所有 HTTP 错误信息中包含：`url`（脱敏）、`model`、`body`（截断），方便排查配置问题
- 新增 `maskUrl()` 方法脱敏 URL（隐藏 query 参数）
- 新增 `shorten()` 方法截断过长响应体
- 新增 `readErrorBody()` 方法读取流式响应的错误体

### 4. 调试日志
- 在 `requestText()` 和 `requestTextStream()` 入口添加 DEBUG 级别日志，记录实际请求 URL、模型名、API 类型

## 排查建议
如果另一台机器仍然 404，请检查：
1. 该机器 AI 配置中的 `openaiBaseUrl` 是否正确（如 qwen 对应 `https://dashscope.aliyuncs.com/compatible-mode/v1`）
2. baseUrl 末尾不要带 `/chat/completions`（代码会自动拼接）
3. 查看 404 错误信息中的 `url=` 字段，确认实际请求的完整路径
